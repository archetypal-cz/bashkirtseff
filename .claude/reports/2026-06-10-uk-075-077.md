## Issues Encountered

- **Translator-generated glossary tags diverge from source (NEW, severe — carnet 075).** Unlike the known path-*depth* drift, tr-a *constructed* tags from scratch: wrong category folders (LARDEREI under `people/suitors/` not `people/mentioned/`; PINCIO under `people/mentioned/` not `places/cities/`), invented entities with no glossary file, over-tagging, and an overall tag set only loosely overlapping the source's. Result: 245 broken links, gate FAIL. **Root cause**: the spawn prompt (and the translator skill) emphasized path *depth* but never said "COPY the source's tags verbatim." tr-b/tr-c, once told mid-flight to copy, produced clean carnets. **This is the headline lesson — see Proposed Changes #1.**
- **Summary-based translation (faithfulness, carnet 075).** tr-a translated 10-28 from summary notes, not source. Caught when fixing tags; rewritten from source. RED+CON then verified the whole carnet via paragraph-ID parity (36/36) + beat-by-beat reads of the long entries — cleared.
- **`just sync` is UNSAFE for translations (tooling).** Tested as a candidate fix for 075's tags (it propagates source annotations). On a backed-up copy it (a) wrote source-depth `../_glossary/` paths → re-broke every link (2244 fails), and (b) **stripped the YAML frontmatter** from all 36 files. Restored from backup; did not use it. The recipe is for `_original`→translation annotation sync but is not depth-aware and is frontmatter-destructive. **Flag for architect.**
- **Gate-gaps — contamination the checks miss (multiple, NEW).** `verify-carnet`'s `latin-in-cyr`/`foreign-script` checks only fire on *mixed* Cyrillic+Latin tokens. They miss: (a) **fully-Latin-script words** embedded in Ukrainian text — Polish «życia», English «Catholic», stray Latin numerals «II»/«I» (red, 075); (b) **Russian-letter contamination** — ы/э/ъ/ё inside Ukrainian words, e.g. «называю» (red-2, 077); (c) **double-UTF-8 mojibake** (from 072–074). All were caught by human review, not the gate.
- **Inline-split-comment artifact (RED → renderer risk, carnet 077).** When RED fixes a word mid-paragraph, its `%%…%%` edit-comment was sometimes spliced onto the *same line* as body text, fragmenting one source paragraph into two pieces around the comment — risking the renderer dropping the trailing half. CON found and fixed 3 in 077 (none in 075/076). Flagged by CON for the editor skill.

## Observations

- **The mechanical gate is the hero of this wave.** tr-a's 245-broken-link tagging reads perfectly fine to a human (the link *text* is correct); only `verify-carnet`'s link-resolution check caught it. Without the pre-RED gate, a badly-tagged carnet would have shipped.
- **Upfront naming lock + CON pre-flag worked.** Baking the Alexandre lock into translator prompts and CON's pre-translation 10-29 mistag flag meant the name collision was resolved in-draft on all three carnets — no downstream scramble like 072–074. The remaining tag problem was orthogonal (categories, not referents).
- **"Copy, don't construct" generalizes.** tr-b/tr-c copying source tags verbatim = clean gates; tr-a constructing = 245 failures. The same is true of the faithfulness issue (translate the source, don't summarize it).
- **Quality held at 0.933** despite 075's turbulence, because the gate + faithfulness reconciliation forced the repair before approval.

## Proposed Changes

1. **Translator SKILL — "copy source glossary tags verbatim; never construct/guess categories" (NEW, top priority).** The biggest defect of this wave. Add to the translator skill's structural-integrity section: glossary tag lines must be copied from the corresponding source entry, changing ONLY the path depth (`../_glossary/` → `../../_original/_glossary/`); do NOT infer category folders (they are not predictable) and do NOT add tags the source lacks. (Backstopped by the pre-RED `verify-carnet` gate, which caught it.)
2. **Faithfulness check = paragraph-ID parity (NEW, cheap mechanical signal).** Comparing source vs translation paragraph-ID counts per entry instantly flags summary-based/under-translated entries (it surfaced tr-a's problem and later confirmed the repair). Worth adding to `verify-carnet` or the ED pre-RED routine. (Note: sentence-count parity is NOT usable — the `_original` files carry `sentence_count_original: 1` placeholders.)
3. **Expand the contamination check (architect).** Accumulating gate-gaps for `verify-carnet`: (a) fully-Latin-script words (not just mixed tokens), (b) Russian-only Cyrillic letters ы/э/ъ/ё in UK text, (c) double-UTF-8 mojibake byte-runs. Plus the carried-over duplicate-paragraph-ID check.
4. **`just sync` is frontmatter-destructive + not depth-aware for translations (architect).** Either fix it to depth-adjust + preserve frontmatter, or document that it must not be run against translation trees.
5. **Editor SKILL — edit-comments on their own line.** When fixing a word mid-paragraph, the `%%…%%` comment must go on its own line, never spliced into the body line (fragments the paragraph; renderer may drop the trailing half). CON found 3 in 077.
6. **TM ruling needed (minor): Prix de Rome.** Rendered «Prix de Rome» (FR, footnoted) in 075 vs «Римська премія» (UK) in 077; both defensible. A TM line would settle future carnets.
