## Issues Encountered

1. **Frontmatter-shape defect (systemic, all carnets).** Translators wrote the *French original's*
   heavy frontmatter (nested `workflow:` block, entities, para ranges) instead of the lean
   translation frontmatter (`date/carnet/language/translation_complete/editor_approved/
   conductor_approved`). `verify-carnet` caught it every time (top-level `translation_complete`
   missing). Notably, agents **self-reported "translation_complete: true ✅"** while the key was
   actually nested — a textbook "verify claims against ground truth" case. Resolved mechanically
   by `normalize_uk_frontmatter.py`, run at each gate. *(WATCHLIST: invisible structural-defect
   class.)*
2. **Homoglyph contamination (088).** Latin `i` (U+0069) inside Cyrillic «Жюліан» in 3 files —
   invisible to a reading review, caught by `verify-carnet`'s `latin-in-cyr` WARN, fixed
   mechanically before RED.
3. **Bracket-canon variance (cross-carnet consistency).** Source `[Mots noircis:]` (blacked-out
   text) is rendered three different ways across the UK corpus: «зачорнено» (071–077), «замазано»
   (088), «затерті» (093, ~90×). Not an error — each is internally consistent — but a corpus-wide
   reconciliation is wanted. **CON-093 recommends «замазано»** as canon (matches 088, closest to
   the ink-blot manuscript reality). *Follow-up: one mechanical normalization pass + TM lock.*
4. **Possible systemic translator pattern: "je rage" → «кленуся».** red-101 flagged "rager"
   (seethe) mis-rendered as «кленуся» (vow/swear) twice; fixed to «лютую». Worth a grep across
   other carnets/languages.
5. **Pre-existing source glossary-tag oddities (out of scope).** Some place tags resolve under
   `people/` in the source (e.g. `#Gambetta`→places/churches, `#Toledo`/`#Madrid`→people/mentioned).
   Translators copied source tags verbatim (correct RED behavior); flagged for glossary-tagger /
   source maintainers.

## Architectural note (important for future runs)

The originally-requested design — "two Opus manager agents, each running its own team" — is **not
achievable in this harness**. The team/spawn/task tools (`TeamCreate`, `Agent`-spawn, `SendMessage`,
`TaskCreate`) are exposed only to the top-level orchestrator; a delegated sub-agent is a leaf and
cannot spawn its own sub-team, regardless of the `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS` flag (which
is on). Both attempted "lead" sub-agents independently hit this wall and cleanly reverted. The
working model is: **the top-level session IS the ED.** One language at a time per session (the user
elected to run CZ separately).
