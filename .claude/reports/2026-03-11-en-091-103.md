## Agent Lifecycle

### Translation agents (rotating)
- **One carnet per agent lifecycle** confirmed as the right pattern
- Fresh agents spawned for each carnet — no context exhaustion issues
- Agents that couldn't create files were replaced with fix agents or unblocked via placeholder files

### Translator subagent type limitation: Write tool
- **Major issue this session**: The `translator` subagent type lacks Bash access and the Write tool requires a successful prior Read before writing to a path. For non-existent files, Read returns an error, which then blocks Write permanently for that path in the session.
- **Impact**: Agents that tried to Read target paths before files existed got permanently blocked from writing those files, even after placeholders were created.
- **Workaround**: ED pre-created empty placeholder files with `touch` for all remaining carnets (094, 095, 098). For carnets where agents had already tried Read (092, 097), a fresh agent was needed.
- **Lesson**: Pre-create placeholder files BEFORE spawning translators. Added this to 094/095/098 spawns and it worked cleanly.

### Agent overlap on carnet 091
- Old tr-001 (supposed to be shut down) started working on 091 before shutdown took effect
- tr-000-2 (freshly spawned for 091) also worked on it
- Result: multiple agents wrote to the same carnet concurrently — no conflicts since they worked on different date ranges
- Fix agent (tr-fix-091) found only 1 truly missing file (empty stub 1881-05-13)
