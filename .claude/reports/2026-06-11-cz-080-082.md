## Issues Encountered

1. **Translator translated 2 entries from a DIFFERENT published edition (NEW defect class, CRITICAL).**
   081/1878-06-23 and 06-24: tr-081 produced French `%%` source blocks + Czech that do NOT
   match our `content/_original/081/` — the distinctive text ("Je suis en deuil de feu Cassagnac",
   "le mort est enterré", "Le Défunt s'appelait Cassagnac") appears NOWHERE in our corpus for
   those dates; it's the realized death-conceit that legitimately belongs to our 06-28+. The
   translator evidently drew on the published "integral" edition / its own knowledge rather than
   our source. **Invisible to `verify-carnet`** (valid French, resolving links) and to a reading
   review; caught ONLY by RED's paragraph-level source comparison (red-081 grepped the whole
   corpus to confirm). Resolution: kept our `_original` (canonical, internally consistent),
   re-translated both from source via a narrow repair agent (tr-081b), re-reviewed by red-081.
   This is distinct from all prior defect classes — it's *wrong-source / external-edition import*,
   not drift or fabrication-within-source. **Strongest argument yet for a paragraph-ID/source-text
   parity check at the gate.**

2. **Translator altered the glossary-tag SET (recurrence of the uk-075-077 class).**
   081/1878-06-23: tr-081 renamed `JOBAL`→`DE_JOBAL` (broke the link — gate-caught) AND invented
   tags (`Maman`, `Paul_de_Cassagnac`) + dropped source tags (`Mme_Gavini`, `Bois_de_Boulogne`).
   The gate caught only the *broken* link; the invented-but-resolving divergence was caught by
   the translator's own re-check + the editor spot-check. red-080/red-082 confirmed NO tag
   tampering on their carnets, so it remains translator-specific, not systemic. The editor
   glossary-tag-fidelity spot-check (added to RED prompts this wave) is the reliable guard for
   the invented-but-resolving case.

3. **Reviewer writing a literal `%%` in comment prose breaks the `%%-balance` gate (NEW pitfall).**
   CON's approval comments on 081/07-26, 081/07-31, and 082/10-04 each contained the literal
   string "%% wrapper" / "the %% French comment", and that embedded `%%` produced an odd marker
   count → gate FAIL. CON self-caught the 082 one; ED fixed the two 081 ones (rephrase to
   "paragraph-ID wrapper" / "embedded French reference copy"). **Cheap, high-value rule: never
   write a literal `%%` inside `%%…%%` comment prose** — surfaced to CON mid-wave.

4. **Re-translator used a nested `workflow:` frontmatter block instead of the carnet's top-level keys.**
   tr-081b wrote `workflow: {translation_complete, …}` but carnet 081 (and the cz tree generally
   here) uses TOP-LEVEL `translation_complete`/`editor_approved`/`modified_by`; `verify-carnet`'s
   frontmatter check requires the top-level key → gate FAIL. ED flattened both files to match the
   45 sibling entries. (Note: 082's TR files carried BOTH a top-level set and a nested workflow
   block; CON added top-level `conductor_approved` and the gate passed — harmless but inconsistent.)

5. **Mid-paragraph RED comment placement (renderer risk, recurrence).** 080/05-24 (080.0307) and
   080/06-13 (080.0667): RED's fix-comment landed mid-paragraph, splitting the Czech body across
   the comment. Gate-clean but a real renderer-drop risk. CON flagged; ED rejoined the text and
   moved the comments to their own lines. Same class as the existing WATCHLIST "Mid-paragraph RED
   comment placement" item.

6. **Idle-wake edit turns after shutdown_request (carried pattern).** Both translators and
   tr-082 applied CON-trap fixes on an idle wake after their shutdown_request. Benign this wave
   (no collisions — handoffs were serialized and the editor→CON acked-shutdown rule from the
   077-079 teamcouch was followed), but the pattern persists.

  and the 074-076 wave (0.90–0.93). No carnet needed wholesale revision; the one re-translation
  was a targeted 2-entry repair, not a carnet redo.

## Proposed Changes

1. **TOP PRIORITY — paragraph-ID / source-text parity check at the gate.** The wrong-edition
   defect (Issue 1) is invisible to every current check. A `verify-carnet` enhancement that, per
   entry, confirms the cz `%%` French source blocks match `_original` paragraph-for-paragraph
   (paragraph-ID set parity + a fuzzy French-text match) would catch both wrong-source import AND
   summary/under-translation (the uk-075-077 paragraph-ID-parity idea). This is now backed by 2
   languages.
2. **Quote-normalization autofix (escalated, 3rd wave).** Add a mechanical ASCII→Czech-curly quote
   pass run at `translation_complete` before RED (or a `verify-carnet --fix`), excluding YAML and
   French `%%` source lines. ~60–70 edits/carnet of pure RED mechanical time, every wave.
3. **Reviewer skill note: no literal `%%` in comment prose** (Issue 3) — a one-line addition to
   the editor + conductor skills; trivial and prevents a recurring self-inflicted gate FAIL.
4. **Frontmatter-format consistency** (Issue 4) — translation files mix top-level keys and nested
   `workflow:` blocks; the gate requires top-level. Worth either standardizing the scaffold or
   making `verify-carnet` accept both. Low priority; ED-fixable in seconds.
5. **Glossary-tag-fidelity spot-check stays in the RED prompt** — it worked this wave; keep it
   until the gate gains an invented-but-resolving-tag check.
