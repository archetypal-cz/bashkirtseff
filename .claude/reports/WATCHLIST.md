# Watchlist

Known patterns and recurring issues to monitor during team runs. Teamcouch reads this to know what to look for in reports.

## Active Issues

### Agent Lifecycle

- [ ] **Context exhaustion mid-carnet** — agents silently stop producing output, no error message. Context compaction fails. Most common with large carnets (35+ entries) or agents doing double-duty (reading originals + translations).
- [ ] **Agents that don't stop** — after completing their carnet, some agents check TaskList for more work instead of stopping. Wastes resources and can cause conflicts.
- [ ] **"interrupted" idle states** — agents go idle with reason "interrupted" without clear cause. May indicate context limit during external API call (e.g., Gemini). Needs investigation.
- [ ] **Agents going off-rails** — occasionally an agent misinterprets its task or starts doing work outside its scope. Usually recoverable with a message, but wastes time.
- [ ] **Shutdown acknowledgment delays** — agents sometimes take multiple idle cycles before responding to shutdown requests. Not harmful but noisy.
- [ ] **Translators finish files but don't finalize task** — translator writes all files and sets `translation_complete: true` but goes idle WITHOUT marking the TR task `completed` or sending a summary, forcing the lead to chase them. 4/6 translators in uk-036-041; related to "Agent message delivery unreliable" (2026-05-24 x2). **Fix applied 2026-05-30**: translator skill now makes finalize (mark complete + summarize) an explicit step distinct from setting `translation_complete`; ED skill adds "watch disk state, nudge" guidance. Monitor for recurrence.
- [ ] **Review-agent idle poll-loops** — RED/CON spawned as teammates wake/check TaskList/re-idle every ~20-30s while their work is blocked, producing churn. 2 reports (uk-031-035, uk-036-041). **Fix applied 2026-05-30**: ED skill now instructs spawning review agents with "wait for ping, don't poll" and pinging per carnet. Monitor.
- [ ] **Critic subagent unavailable in team mode** — translator skill Phase 3 Pass 1 says to spawn an Opus grammar/naturalness critic via the Task tool, but teammates spawned via the Agent tool have no Task tool, so it's impossible in team mode (worked in non-team mode, e.g. uk-006-008). 2 team-mode reports (uk-031-035, uk-036-041); translators fell back to manual self-review at 0.95-0.96 quality. **Fix applied 2026-05-30**: translator skill clarified — team teammates do the self-review pass manually. Monitor.
- [ ] **Session-pause ping loss** — across a long session pause/resume, an in-flight team message (a CON ping for carnet 032) was dropped; the task sat pending with all entries editor-approved. 1 instance (uk-031-035). Caught by disk-state check. ED skill now says verify on disk after interruption. Watch for recurrence.
- [ ] **Conductor subagent type immediate idle/death** — conductor spawned as `conductor` subagent type went idle immediately without doing work (con), or partially completed then died mid-task marking it done prematurely (con-2). Workaround: spawn as `general-purpose`. Needs confirmation — 1 report only (2026-03-05-en-036-041).
- [ ] **Write tool path tracking bug** — when a translator agent attempts to `Read` a file that doesn't exist yet, the Write tool permanently blocks that path for the entire agent session. Workaround: pre-create empty placeholder files (`touch content/{lang}/{carnet}/*.md`) before spawning translators. Confirmed in 3 reports (en-065-070, en-093-106, en-091-103). ED skill should document this as standard practice.
- [ ] **Concurrent edits to the same carnet (translator cleanup pass vs RED)** — a translator's post-convention cleanup pass (e.g. dialogue-quote conversion) ran on the same carnet RED was simultaneously reviewing; both edited overlapping files. Because both used line-level `Edit` (not full-file `Write`), the changes coexisted with no data loss — but it was luck, not design. **Serialize: a translator cleanup pass and RED review must not run on one carnet at once.** Also seen: a just-shut-down translator (tr-4) surfaced a *stale* "still needs fixing" list for work another agent had already completed and committed (git showed 0 changes since commit — its edits never hit disk). 1 report. Report: 2026-05-31-cz-050-055.md.
- [ ] **ED/reviewer acting on an agent claim that ground truth contradicts** — agents assert things (a cross-carnet term "collision", which carnet is the style outlier, a "still incomplete" list) that disk/source verification disproves; acting on the claim risks a wrong "fix". uk-050-055: ED nearly normalized «Сорока» (Marie's *authorial reuse* of a magpie pet-word for different men) as if it were translator drift — red2 verified against source and reverted. cz-050-055: RED+CON both said 051 was the em-dash outlier (grep proved 053); tr-4's stale completeness claim contradicted by git. **Verify claims against source/disk before acting on them.** 2 reports (uk-050-055 proposed this as an ED edit but was never teamcouched). On a 3rd instance, add to ED skill. Reports: 2026-05-30-uk-050-055.md, 2026-05-31-cz-050-055.md.

### GEM Corruption Patterns

- [ ] **Inline GEM comments splitting paragraph text** — Gemini places `%% GEM: ... %%` mid-paragraph ~50% of the time, despite explicit prompt instructions. Currently caught by manual audit or RED review.
- [ ] **Gemini translating French in comments** — Gemini occasionally "translates" the French original text inside `%% ... %%` comments, corrupting the source reference.
- [ ] **Duplicate paragraph insertion** — Gemini copies a paragraph block, resulting in duplicate IDs and text.
- [ ] **Removed markup** — Gemini strips `==highlight==` markup on code-switches or removes footnote references.

### Translation Quality

- [ ] **Gallicism rates** — track frequency of gallicisms caught by GEM/RED/OPS per carnet. High rates may indicate translator needs updated guidance.
- [ ] **False friend frequency** — especially for Czech (ceremonie, kostým, kabinet) and English (sympathetic, actually, revolt/révolter, eve/veille, vilain/naughty). New EN false friends found in 008-010 run (2026-02-16).
- [ ] **Quality score trends** — CON scores should trend upward as skills improve. Czech: 0.937 avg (016-021) → 0.970 avg (022-027). Quality jump attributed to RED as general-purpose (direct fixes) and polarity check addition. English: stable at 0.95-0.96 range — plateau reached. Ukrainian: 0.94 → 0.947 → 0.952 → 0.953 → 0.952 → 0.96 → 0.956 (w7, 031-035) → 0.963 (w8, 036-041) avg — plateau at 0.95-0.96, w8 the highest cluster yet.
- [ ] **Orphaned footnotes** — translators define footnote definitions (`[^xxx]: ...`) but forget the in-text superscript marker (`[^xxx]`). 6 instances across 4 carnets and 2 of 3 translators in 042-047 run. tr-002 had zero in carnet 047. Caught by RED. Proposal: add footnote-linking self-check to translator skill. Reports: 2026-03-05-en-042-047. Needs confirmation — 1 report only.
- [ ] **Code-switch misidentification** — EN translators highlighted French idioms as English code-switches in 2 instances (009, 010). "It takes my breath away" and "that's all I'm saying!" were translated French idioms, not Marie writing in English. Needs confirmation — 1 report only (2026-02-16).
- [ ] **Footnote ID format inconsistency** — EN translators use two formats: `[^fn047-034]` (fn+carnet-seq) and `[^45.266.1]` (carnet.para.seq). Both valid markdown, but inconsistent across carnets. 125 occurrences of fn-format vs 58 of para-format. Consider standardizing. Reports: 2026-03-05-en-042-047, also observed across 001-003 and 036-047.

### Glossary Research

- [ ] **Paragraph ID granularity variance** — glossary research agents produce wildly different PID densities (16 PIDs/245 lines vs 70 PIDs/286 lines). Not a quality issue yet, but may cause confusion if PIDs are referenced elsewhere. Confirmed across 6 batches (50 entries). Not blocking. Reports: 2026-05-24-glossary-top15, 2026-05-25-glossary-research.
- [ ] **glossary-merge appends cruft** — the merge tool does "simple append" of the full source file content to the target, requiring manual cleanup after every merge. Consider adding a `--no-append` or `--clean` flag. 6 merges required manual cruft removal. Report: 2026-05-25-glossary-research.
- [ ] **GIOIA miscategorized as places/cities** — person entry (Amélie Gioia, demi-mondaine) filed under places/cities/ due to early auto-generation error. 222+ content links prevent easy move. Report: 2026-05-25-glossary-research.
- [ ] **Translator copies source glossary paths without depth adjustment** — translators copy `%% [#Tag](../_glossary/…) %%` tags verbatim from `content/_original/{carnet}/`, but from `content/{lang}/{carnet}/` the correct relative path is `../../_original/_glossary/…`. tr-5 (055) + tr-6 (050) did this → **1,515 broken links across 65 entries**. The defect is invisible to a reading review (link *text* looks fine) and **slipped past both RED and CON**; caught only by an ED link-resolution grep. tr-1–tr-4 got it right, so it's translator-dependent, not skill-systemic — but a mechanical check would catch it regardless. **Tooling added 2026-05-31**: `just check-links {lang} {carnet}` (and `just check-links-all {lang}`) flags any relative `.md` link whose target doesn't resolve from the file's location — run it before committing a translated carnet, and consider adding link-resolution to the RED checklist. **All known cz instances fixed 2026-05-31** (050, 055, 001, 009, 011, 095 — sed + check-links verified clean). Still a watch: translators may reintroduce it; check-links is the guard. Report: 2026-05-31-cz-050-055.md.
- [ ] **Stale glossary paths in older carnets (cz 010/018/019 FIXED 2026-05-31)** — two legacy link styles broke after the glossary was reorganized into subcategories: (a) missing-subcategory paths (`people/ANITCHKOFF.md` → actual `people/recurring/ANITCHKOFF.md`; many also cross-category, e.g. `people/MILORADOVITCH.md` → `culture/literature/`), and (b) an older site-root style with bare TitleCase names (`/_original/_glossary/Dina.md` → `../../_original/_glossary/people/core/DINA.md`). **Fixed** by basename-resolution remap (find actual location, rewrite to relative path): 010, 018, 019 — 85 unique targets remapped, all now pass `just check-links`. **Likely still affects `_original/` and other languages** (uk/en/fr) — a `check-links-all` sweep of each language would surface them; the same basename-remap approach applies. Reports: 2026-05-31-cz-050-055.md.
- [ ] **Orphaned theme tag with no source basis (`[#Marriage]`/MARRIAGE.md)** — cz 018 (1874-04-10) has 2 `[#Marriage](.../culture/themes/MARRIAGE.md)` tags, but no MARRIAGE.md entry exists anywhere AND the French source doesn't tag marriage at all (closest theme: LOVE.md) — a translator-introduced tag pointing nowhere. Not a stale path; needs a content decision: create a MARRIAGE theme entry (RSR), retarget to LOVE.md, or remove the orphaned tags. Left as-is pending decision. 1 report. Report: 2026-05-31-cz-050-055.md.

If 5 runs pass with no evidence, consider resolving. Reports: 2026-02-16-en-008-009-010.md, 2026-02-16-uk-006-008.md, 2026-02-17-uk-009-011.md, 2026-02-17-uk-012-014.md.

### Ukrainian-Specific

- [ ] **Dialogue-punctuation convention inconsistency (cross-language)** — translators choose different dialogue markers and it diverges per-carnet/per-translator because the translator skill states no explicit convention. UK: `---` (3 hyphens) vs `—` (em dash), uk-006-008. CZ: line-start em-dash (053, tr-4) vs Czech curly quotes „…" (the house style across 49 prior carnets + 5/6 of the batch), cz-050-055 — required a dedicated post-hoc conversion pass on 053. 2 reports / 2 languages. **On a 3rd instance, add an explicit per-language dialogue-punctuation convention to the translator skill** (CZ: „…" curly quotes for direct speech, never line-start em-dashes in body; speaker tags split the quote). Sub-note: in cz-050-055 both RED and CON *misidentified which carnet was the outlier* (said 051; grep proved it was 053) — trust a mechanical grep over agent recollection for consistency questions. Reports: 2026-02-16-uk-006-008.md, 2026-05-31-cz-050-055.md.
- [ ] **Fix rate trend (UK)** — declining across 8 waves: 0.42 → 0.28 → 0.22 → 0.31 → 0.27 → 0.14 → 0.08 (w7) → 0.05 (w8) /entry. Quality improving: 0.94 → 0.947 → 0.952 → 0.953 → 0.952 → 0.96 → 0.956 → 0.963. Plateau at 0.95-0.96; w7-w8 fix rate near-zero (2 cosmetic fixes total in w8, 0 CON edits). Reports: all 8 UK reports.
- [ ] **Cyrillic contamination** — Latin characters embedded in Cyrillic words ("Тумanchoфи"), Russian ё/ы in Ukrainian text, Chinese character 历. Appeared in 2 reports (2026-05-24). Not seen in Feb reports. May be model artifact. Watch for recurrence.
- [ ] **Fabricated words (cross-language)** — translators generate nonexistent words. Ukrainian: "збільшувально", "боянним", "спіла" (uk-018-022). Czech: "voitře" (cz-016-021). 3 reports across 2 languages. Translator skill updated with fabricated word warning (2026-05-24).
- [ ] **Agent message delivery unreliable** — agents complete tasks and mark them done, but completion messages don't reach team lead. Requires proactive task/file state checking. 2 instances (2026-05-24) + reinforced by uk-031-035/uk-036-041 (session-pause ping loss; translators idling pre-finalize). Infrastructure issue; mitigated by disk-state checking (now in ED skill). See also "Translators finish files but don't finalize task" and "Session-pause ping loss" above.
- [ ] **Code-switch visibility loss (UK)** — Marie's deliberate Cyrillic "мене" inside French text becomes invisible in Ukrainian translation. CON resolved with footnote in 024.0207. 1 report only (2026-05-24-uk-023-025). Document as standard practice if recurs.

## How to Update

- **New pattern observed once**: Add to Active Issues with a `[ ]` checkbox and "Needs confirmation" note
- **Pattern confirmed (3+ occurrences)**: Remove "Needs confirmation", add occurrence count
- **Pattern resolved**: Move to Resolved Issues with `[x]` checkbox and date
- **Teamcouch updates**: `/teamcouch` may propose additions/removals based on report analysis
