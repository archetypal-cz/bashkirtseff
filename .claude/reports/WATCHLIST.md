# Watchlist

Known patterns and recurring issues to monitor during team runs. Teamcouch reads this to know what to look for in reports.

## Active Issues

### Agent Lifecycle

- [ ] **Context exhaustion mid-carnet** — agents silently stop producing output, no error message. Context compaction fails. Most common with large carnets (35+ entries) or agents doing double-duty (reading originals + translations). **Oversized-single-entry variant (uk-056-061)**: carnet 060's 1876-05-19 was a *single* 363-paragraph entry (whole carnet 884 paras); tr-060 finished 7/9 entries then stalled with zero progress on it and went idle without replying. Mitigation that worked: retire the stalled agent, spawn a FRESH-context replacement for just the remaining entry(ies), and instruct it to translate+SAVE in ~30-paragraph batches (never hold the whole entry in memory). **CONFIRMED 2nd instance → translator SKILL updated 2026-06-14:** cz-104-106, carnet 106's `1884-10-07.md` (a single 277-paragraph file, the Aug 8–31 Bastien-cancer stretch) killed **two** consecutive translators — not on context but on the **32k assistant-OUTPUT-token limit** (verbose per-paragraph narration). A third translator dedicated to ONLY that file, instructed to keep narration minimal + batch-save, finished all 277 in one clean run. The binding limit for oversized entries is OUTPUT budget, not context. Translator SKILL now has an "Oversized single entries (>~150 paragraphs)" section (batch-save + minimal narration). Reports: 2026-06-06-uk-056-061.md, 2026-06-14-cz-104-106.md.
- [ ] **Agents that don't stop** — after completing their carnet, some agents check TaskList for more work instead of stopping. Wastes resources and can cause conflicts.
- [ ] **"interrupted" idle states** — agents go idle with reason "interrupted" without clear cause. May indicate context limit during external API call (e.g., Gemini). Needs investigation.
- [ ] **Agents going off-rails** — occasionally an agent misinterprets its task or starts doing work outside its scope. Usually recoverable with a message, but wastes time.
- [ ] **Shutdown acknowledgment delays** — agents sometimes take multiple idle cycles before responding to shutdown requests. Not harmful but noisy.
- [ ] **Translators finish files but don't finalize task** — translator writes all files and sets `translation_complete: true` but goes idle WITHOUT marking the TR task `completed` or sending a summary, forcing the lead to chase them. 4/6 translators in uk-036-041; related to "Agent message delivery unreliable" (2026-05-24 x2). **Fix applied 2026-05-30**: translator skill now makes finalize (mark complete + summarize) an explicit step distinct from setting `translation_complete`; ED skill adds "watch disk state, nudge" guidance. Monitor for recurrence.
- [ ] **Review-agent idle poll-loops** — RED/CON spawned as teammates wake/check TaskList/re-idle every ~20-30s while their work is blocked, producing churn. 2 reports (uk-031-035, uk-036-041). **Fix applied 2026-05-30**: ED skill now instructs spawning review agents with "wait for ping, don't poll" and pinging per carnet. Monitor.
