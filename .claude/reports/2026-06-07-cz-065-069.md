### Process / tooling
1. **`verify-carnet` gate adopted and paid off** — run pre-RED on all 5; caught an
   **orphaned footnote in 069/1877-03-28** (def `[^069.476.1]` mis-numbered vs ref
   `[^069.499.1]`; ED-fixed to match paragraph 0499). Resolves last wave's adoption gap.
2. **GATE GAP — `verify-carnet` does NOT catch duplicate paragraph IDs.** red-a found **6
   duplicate IDs** in 068 (heading-block sharing a content-block ID) that the gate passed.
   **Propose: add a duplicate-paragraph-ID check to `verify-carnet`** (and a missing-ID
   check). Editors should keep a manual dup-ID grep meanwhile.
3. **Translator subagent has no shell** — the `translator` subagent type lacks Bash, so it
   **cannot run `just verify-carnet`** despite the translator skill instructing it to. The
   ED-run pre-RED gate covers this, but the translator-skill step is unexecutable in team
   mode. (Same family as the prior "critic subagent unavailable in team mode" finding.)
   Translators did run manual greps and self-caught conditionals — that part works.
4. **CON batch-sets `conductor_approved` at end of carnet** — so disk-count stays flat at
   0/N during the read then jumps to N/N. Don't interpret 0/N as "stuck." **New protocol
   adopted this wave: CON sends a ~halfway heartbeat on big carnets** — worked well,
   eliminated false-stall alarms.
5. **Conductor collision from parallelizing too eagerly** — spawning con2 onto 069 before
   con had acknowledged its "do 066→067 only" redirect put both on 069. **Lesson: confirm
   an agent's redirect ack BEFORE spawning a parallel agent onto the same carnet.** No data
   loss this time (luck of line-level edits), but the same class as the WATCHLIST
   "concurrent edits to the same carnet" item.
6. **Agent claim contradicted by disk (again)** — red-b reported 069 had reached RED 36/36
   when disk showed 10/36 (off by 26). Verified before acting; no wrong action taken. Nth
   instance of the agent-claim-vs-ground-truth pattern.

## Observations

- **Dynamic scaling is the headline.** Three big carnets with 2 base editors would have
  bottlenecked; scaling to 4 editors (with a tail-split + fresh relief) and 2 conductors
  kept all three reviewing in parallel. Context tripwires + fresh-context relief prevented
  any wall. ~145 entries in ~2h20m.
- **The gate + heartbeat protocols both worked** and should become standard: ED runs
  `verify-carnet` pre-RED; CON heartbeats at halfway on 30+-entry carnets.
- **The cost of over-eager parallelism** was the con/con2 collision — parallelize, but
  serialize the *handoff* (confirm ack before spawning).
- Error profile remained **mechanical/semantic, not structural** — hard literary passages
  (Já Sama anaphora, the nightingale climax, the 84-para mandolin/duel, the peasant
  wedding) came through clean.

## Proposed Changes

1. **`verify-carnet`**: add a duplicate-paragraph-ID check (and missing-ID check) — issue #2.
2. **ED skill**: when parallelizing a stage (2nd editor/conductor), **confirm the existing

   codify the CON halfway-heartbeat for 30+-entry carnets (issue #4).
3. **translator skill**: note that `verify-carnet` is ED-run (translator subagent can't
   shell) — keep the translator's manual greps (issue #3).
