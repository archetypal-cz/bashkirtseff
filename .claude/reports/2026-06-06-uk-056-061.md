## Issues Encountered

1. **Anthropic API overload (~09:20–10:14, ~55 min)** — the entire team froze mid-run: CON (hadn't started 056), RED (hadn't started 059), and tr-060b (hadn't started 05-19) all stalled with their processes alive but idle. Detected via disk mtimes (nothing written for ~53 min). **All three recovered cleanly on a wake-up ping — zero data loss.** Earlier committed flags/edits were intact on disk. Lesson: disk-mtime monitoring is the reliable liveness signal; a simple resume ping revived live-but-idle processes without respawn.

2. **Scaffold path-depth bug (known gotcha)** — `just scaffold` emits source-relative glossary paths `../_glossary/…`; translations live one level deeper and need `../../_original/_glossary/…` (per `docs/GLOSSARY_LINK_MAINTENANCE.md`). All 6 scaffolded carnets had broken links (057 alone: 136/136). Fixed per-carnet with a targeted idempotent sed as each landed; final `check-links-repo` = 0 broken. **Not a new bug — documented behavior of scaffold/sync.**

3. **Pietro spelling drift — THREE variants** — canonical is «П'єтро» (established 050-055). Translators who read the TM before the canonical line landed drifted to «Піетро» (і-е, tr-057/056) AND «Пієтро» (і-є, tr-060). A grep for only «Піетро» **missed the «Пієтро» variant** — caught by RED (31× in 060). Normalized carnet-wide every time; TM line hardened to list all three drift variants (Піетро/Пієтро/Пьетро) + Petruccio + the «Pietro*» asterisk code-marker. Added a canonical TM line mid-wave.

4. **Single oversized entry (060/05-19, 363 paras)** — larger than most whole carnets; caused tr-060's stall (context saturation after 7 entries). Resolved by a fresh-context replacement (tr-060b) instructed to translate in ~30-para durable batches with frequent saves. **Lesson: for any entry >~150 paras, instruct incremental batch-saving up front, and consider giving an oversized entry its own fresh translator.**

5. **Cross-carnet name reconciliation (all caught by RED)** — Larderei → «Лардереї» (×29 across 056/059/060), Zucchini → «Зуккіні» (×7), Galula → «Ґалула» (×11), Фанні Лір (aligned across 056/057/059), «Марі» indeclinable (not «Марія»), «готель де ла Вілль». TM updated with canonical forms.

6. **Fanny Lear footnote — historical error (fixed)** — 057.0088 named real name «Хетті Блюм» and grand duke «Миколи Олександровича»; both wrong. Corrected to Harriet "Hattie" Blackford, mistress of Grand Duke **Nikolai Konstantinovich** (the 1874 diamond-theft scandal); reconciled with the parallel 058.0056 footnote. **TODO (source-side):** the `FANNY_LEAR` glossary entry is an auto-generated stub — needs proper RSR research.

7. **Latin-in-Cyrillic contamination (recurring, all caught by RED)** — translators repeatedly leaked Latin letters into Cyrillic names/words (Лорантi, Рубандi, Граcій, баронe, моindре, «Поitrinaire») plus stray apostrophes (Віскон'ті, Ларде'рей). Heaviest in 061. RED caught every instance; final text is clean.

8. **TODO (source-side): 059 04-20 location** — source frontmatter says `location: Paris` but the entry is the Rome races; the UK faithfully mirrors the RSR value. Flag for source-side RSR correction.

- **Persistent reviewers scale to ~6 carnets here without context failure** — RED handled all 6 (incl. the 884-para 060) and CON all 6; neither stalled from accumulated context. The translators, not the reviewers, were the context-limited role this wave (the 363-para entry).

## Proposed Changes

1. **translator SKILL**: add explicit guidance — "For any single entry over ~150 paragraphs, translate and SAVE in ~30-paragraph batches; never hold the whole entry in memory before writing." (tr-060 stall.)
2. **executive-director SKILL / scaffold workflow**: note that `just scaffold` produces source-relative `../_glossary/` paths that MUST be path-depth-fixed for translations (`../../_original/_glossary/`); run `check-links-repo` before commit. (Recurring per-wave.)
3. **executive-director SKILL**: when checking name/term drift via grep, grep ALL plausible misspelling variants, not one — the «Пієтро» (і-є) variant was missed by a «Піетро» (і-е)-only grep. (Pietro episode.)
4. **Process / resilience**: codify the overload-recovery play — detect freeze via disk mtimes (not idle notifications), send a resume ping to live-but-idle agents before respawning, and only respawn if a ping yields no new disk write within a few minutes. (Worked cleanly here.)
5. **researcher / glossary**: `FANNY_LEAR` stub needs real research; 059 04-20 source `location` likely wrong (Paris vs Rome). Both logged as source-side TODOs.
